# B-B-13 調査結果

## 結論

確認用パスワードとの一致チェックと、不一致時にオンボーディングが完了しない動作は、既存実装およびテストで確認できるため、機能修正・重複テストの追加は不要と判断しました。

## 対応済みと判断した根拠

- [`OnboardingRequest`](../app/Http/Requests/Auth/OnboardingRequest.php) の `password` ルールに Laravel の `confirmed` が指定されています。このルールは `password_confirmation` との一致を検証します。
- [`OnboardingTest`](../tests/Feature/Auth/OnboardingTest.php) の `test_store_rejects_mismatched_password_confirmation` は、異なるパスワードを送信した場合に `password` の入力エラーがセッションに設定され、ユーザーの状態が `invited` のままであることを確認しています。

## 422 の記載と仕様差異

チケットには不一致時に HTTP 422 になると記載されています。一方、オンボーディングは通常の HTML フォーム送信であり、PM確認では HTTP 422 の返却ではなく、入力エラーが表示され登録が進まないことを確認する方針です。

既存テストも、422 ステータスではなく入力エラーと登録未完了を検証しています。よってチケット記載のステータスコードと合意された期待動作には差異がありますが、利用者に対するバリデーション要件は既存実装で満たされています。
